# ワイヤーフレームの新規作成

引数：$ARGUMENTS

## 1. 引数を読み取る

- 最初の語が画面 ID（例：`sc03`。英小文字と数字）
- 2 つ目の語が名前（例：`list`。英小文字とハイフン）。ファイル名は `wf-<画面ID>-<名前>.drawio` になる
- 残りが画面の内容
  - 「pc のみ」「sp のみ」と書かれていれば、そのページだけ作る。書かれていなければ、`pc` と `sp` の 2 ページを作る
- 画面 ID か名前がない、または画面の内容が空のときは、作業を始めずに、必要な引数を示して聞き返す

## 2. 描く前に、要素の一覧を示して確認を取る

- `drawio-wireframe` スキルの `references/rules.md` と `references/catalog.md` を読んでから、一覧を作る
- 内容から、画面に必要な要素を一覧にする
  - ファイル名とページ構成
  - 部品（カタログの「採用」にある図形から選ぶ。画面内の位置の見当と、標準の大きさも書く）
  - 注釈（番号をつける対象と、書く内容）
- 内容に書かれていないことは推測で埋めず、「不明点」として一覧の最後に挙げる
  - 例：入力項目の種類、ボタンの名前、遷移先、表示する件数、必須かどうか
  - 画面の中身がほとんど書かれていないときは、最小構成の案を示して、確認を取る
- 内容が `pc` の 800 や `sp` の 812 に収まらなそうなときは、画面枠を伸ばす旨と、下端の点線を置くことを、一覧に書く
- 一覧を示したら、ここで止めてユーザーの確認を待つ

## 3. 図を作る

- 確認が取れたら、`drawio-wireframe` スキルの手順とルールに従って作る
- 同じ名前のファイルがすでにあれば、上書きせずに、名前に区別できる語を足した別のファイルにする（例：`wf-sc03-list-buttons.drawio`）
- 作成中は、`.drawio` を VS Code の draw.io エディタで開かない

## 4. チェックして、書き出して、報告する

- 保存すると、hook がチェックスクリプトを実行する。エラーが返ってきたら、すべて直す
- `scripts/export_wireframe.sh outputs/wireframes/drawio/<ファイル名>.drawio` で、作成した図だけを書き出す
- 書き出された PNG を読み込んで、見た目を確認する。直したら、チェックと書き出しをやり直す
  - 書き出しが失敗したときは、チェックが通っていても、原因を調べる（例：`mainText` が数字だけ）
- 報告には、次の 2 つを含める
  - `drawio-wireframe` スキルの「作成後のセルフチェック」の結果
  - `export_wireframe.sh` の実行結果（OK / NG と、出力した SVG と PNG のパス）
- `review/wireframes.md` への反映と、コミットは、ユーザーに頼まれるまでしない。報告の最後に、反映とコミットが必要か聞く
